## 1. Numeración de contratos (diseño ajustado — con módulo de configuración)

### Contexto

`api/prevision_contratos.php` tiene hoy `proximo_numero()`: solo `MAX(numero)+1`, sin
canal ni año, y con una condición de carrera real (dos contratos creados casi
simultáneamente pueden calcular el mismo `MAX` antes de que el primer `INSERT` se
confirme). El campo `prev_contratos.origen` (VARCHAR(60)) ya existe en la tabla pero
**no se usa en la UI hoy** — se puede reutilizar para el canal de venta en vez de crear
una columna nueva.

Ajuste respecto a la primera versión de este plan: el **ID interno único** de un
contrato sigue siendo `prev_contratos.id` (ya existe, nunca cambia). El **número
mostrado** (`prev_contratos.numero`) se separa en su propia tabla con historial, y el
patrón/formato del número deja de estar fijo en código — se vuelve **configurable desde
un módulo de administración**, con vista previa antes de confirmar.

### Formato (configurable, no fijo)

Por defecto: `FDZ-{CANAL}-{AAAA}-{SECUENCIAL}` (ej. `FDZ-WEB-2026-000001`), pero cada
componente se puede activar/desactivar y ajustar desde la UI de configuración (sección
"UI de configuración" más abajo): incluir o no el código de empresa, incluir o no el
canal, incluir o no el año (y con cuántos dígitos, 2 o 4), cuántos dígitos tiene el
secuencial, y qué separador usar.

### Tablas nuevas

```sql
-- Catálogo de canales de venta (editable desde la UI, sin tocar código)
CREATE TABLE IF NOT EXISTS prev_canales_venta (
  id      SMALLINT UNSIGNED NOT NULL AUTO_INCREMENT,
  codigo  VARCHAR(10) NOT NULL,
  nombre  VARCHAR(60) NOT NULL,
  activo  TINYINT(1) NOT NULL DEFAULT 1,
  PRIMARY KEY (id),
  UNIQUE KEY uq_prevcv_codigo (codigo)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

INSERT IGNORE INTO prev_canales_venta (codigo, nombre) VALUES
  ('WEB', 'Página web'),
  ('VEN', 'Vendedor independiente'),
  ('OFI', 'Oficina / venta directa');

-- Configuración del patrón de numeración. Cada cambio inserta una fila nueva
-- (versionado) en vez de editar en sitio, y desactiva la anterior — así cada
-- número generado queda ligado (config_id) al patrón vigente en ese momento,
-- sin ambigüedad si el patrón cambia después.
CREATE TABLE IF NOT EXISTS prev_numeracion_config (
  id                  TINYINT UNSIGNED NOT NULL AUTO_INCREMENT,
  incluir_empresa     TINYINT(1) NOT NULL DEFAULT 1,
  codigo_empresa      VARCHAR(10) NULL DEFAULT 'FDZ',
  incluir_canal       TINYINT(1) NOT NULL DEFAULT 1,
  incluir_anio        TINYINT(1) NOT NULL DEFAULT 1,
  digitos_anio        TINYINT UNSIGNED NOT NULL DEFAULT 4,  -- 2 o 4
  digitos_secuencial  TINYINT UNSIGNED NOT NULL DEFAULT 6,
  separador           VARCHAR(3) NOT NULL DEFAULT '-',
  activo              TINYINT(1) NOT NULL DEFAULT 1,
  created_at          TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  created_by          BIGINT UNSIGNED NULL,
  PRIMARY KEY (id),
  CONSTRAINT fk_prevnumcfg_usuario FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

INSERT INTO prev_numeracion_config (incluir_empresa, codigo_empresa, incluir_canal, incluir_anio, digitos_anio, digitos_secuencial, separador, activo)
VALUES (1, 'FDZ', 1, 1, 4, 6, '-', 1);

-- Contador atómico. "periodo" es el año si el patrón activo incluye año, o un
-- valor fijo ('0') si no — así el contador nunca se resetea por año cuando el
-- año no aparece en el número (si se reseteara igual, se duplicarían números
-- entre años).
CREATE TABLE IF NOT EXISTS prev_numero_contadores (
  canal   VARCHAR(10) NOT NULL,
  periodo VARCHAR(10) NOT NULL,
  ultimo  INT UNSIGNED NOT NULL DEFAULT 0,
  PRIMARY KEY (canal, periodo)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- Separa el ID interno (prev_contratos.id, inmutable) del número mostrado, con
-- historial completo. prev_contratos.numero sigue existiendo como espejo del
-- número vigente (para no romper reportes/recibos que ya lo usan), pero la
-- fuente de verdad y el historial de ajustes viven aquí.
CREATE TABLE IF NOT EXISTS prev_contrato_numeros (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  contrato_id   BIGINT UNSIGNED NOT NULL,
  numero        VARCHAR(30) NOT NULL,
  canal         VARCHAR(10) NULL,
  anio          SMALLINT UNSIGNED NULL,
  secuencial    INT UNSIGNED NULL,
  config_id     TINYINT UNSIGNED NULL,
  vigente       TINYINT(1) NOT NULL DEFAULT 1,
  motivo_ajuste VARCHAR(255) NULL,
  generado_por  BIGINT UNSIGNED NULL,
  created_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uq_prevconnum_numero (numero),
  KEY ix_prevconnum_contrato (contrato_id, vigente),
  CONSTRAINT fk_prevconnum_contrato FOREIGN KEY (contrato_id) REFERENCES prev_contratos(id) ON DELETE CASCADE,
  CONSTRAINT fk_prevconnum_config FOREIGN KEY (config_id) REFERENCES prev_numeracion_config(id),
  CONSTRAINT fk_prevconnum_usuario FOREIGN KEY (generado_por) REFERENCES users(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### Generación atómica (reemplaza `proximo_numero()`)

MySQL soporta un patrón estándar y atómico con `ON DUPLICATE KEY UPDATE` +
`LAST_INSERT_ID(expr)` — una sola sentencia, sin `SELECT ... FOR UPDATE` ni locks
manuales, sin la condición de carrera del `MAX()+1` actual. Lee la configuración activa
en vez de tener el formato fijo en código:

```php
/** Config de numeración activa (la última fila con activo=1). */
function prev_numeracion_config_activa(): array
{
    $r = db()->query("SELECT * FROM prev_numeracion_config WHERE activo = 1 ORDER BY id DESC LIMIT 1")->fetch();
    if (!$r) json_out(['ok' => false, 'error' => 'No hay configuración de numeración activa.'], 500);
    return $r;
}

/** Genera el siguiente número de contrato para un canal, según la configuración activa. */
function prev_generar_numero(string $canal): array
{
    $cfg = prev_numeracion_config_activa();
    $canal = prev_canal_valido($canal) ?: prev_canal_default(); // valida contra prev_canales_venta activos
    $anio = (int)date('Y');
    $periodo = $cfg['incluir_anio'] ? (string)$anio : '0';

    $pdo = db();
    $pdo->prepare(
        "INSERT INTO prev_numero_contadores (canal, periodo, ultimo) VALUES (?, ?, 1)
         ON DUPLICATE KEY UPDATE ultimo = LAST_INSERT_ID(ultimo + 1)"
    )->execute([$canal, $periodo]);
    $secuencial = (int)$pdo->lastInsertId();

    $partes = [];
    if ($cfg['incluir_empresa']) $partes[] = $cfg['codigo_empresa'];
    if ($cfg['incluir_canal'])   $partes[] = $canal;
    if ($cfg['incluir_anio'])    $partes[] = $cfg['digitos_anio'] == 2 ? substr((string)$anio, -2) : (string)$anio;
    $partes[] = str_pad((string)$secuencial, (int)$cfg['digitos_secuencial'], '0', STR_PAD_LEFT);

    return [
        'numero' => implode($cfg['separador'], $partes),
        'config_id' => (int)$cfg['id'], 'canal' => $canal, 'anio' => $anio, 'secuencial' => $secuencial,
    ];
}
```

Al crear un contrato: generar el número, insertar en `prev_contrato_numeros`
(`vigente=1`), y copiar el valor a `prev_contratos.numero` (se mantiene la posibilidad
de que el staff tipee un número manual, igual que hoy — solo cambia el valor por
defecto cuando se deja en blanco).

### UI

**Sub-pestaña nueva "Numeración"** (dentro de Previsión → Configuración, junto a
"Ajustes de tarifas" y "Catálogos" que ya existen), con dos secciones en la misma
pantalla:

1. **Patrón del número**: formulario con los campos de `prev_numeracion_config`
   (checkboxes de qué incluir, selects de dígitos, campo de separador). Cada vez que se
   toca un campo, se recalcula y muestra en vivo un **ejemplo real** del número
   resultante (ej. `FDZ-WEB-2026-000001`) — el admin revisa esa vista previa antes de
   confirmar. Al guardar, se inserta la nueva fila de config (versionada) y se
   desactiva la anterior.
2. **Canales de venta**: CRUD de `prev_canales_venta` (código, nombre, activo) —
   mismo patrón que ya usa "Catálogos" hoy.

**Formulario de "Nuevo contrato"**: agregar el `<select>` de canal de venta (poblado
desde `prev_canales_venta`), guardando en el campo `origen` que ya existe.

**Detalle del contrato**: botón **"Corregir número"** — abre un formulario que permite
generar un número nuevo (con la config activa) o escribir uno manual, pidiendo un
**motivo obligatorio**. Al confirmar: marca la fila `vigente` anterior en
`prev_contrato_numeros` como `vigente=0`, inserta la nueva como `vigente=1`, y
actualiza `prev_contratos.numero`. Queda auditado quién, cuándo y por qué se corrigió.

### Migración de contratos existentes

**No se renumeran** los contratos ya creados — son documentos ya entregados a clientes.
El esquema nuevo aplica solo a contratos creados después de este cambio. (Opcional, no
bloqueante: se puede hacer un `INSERT` de respaldo en `prev_contrato_numeros` con el
`numero` actual de cada contrato existente, `vigente=1`, `config_id=NULL`, solo para que
el historial quede completo desde el arranque — no es necesario para que el sistema
funcione.)
